# Protocol 초안 작성

**이 작업에는 피험자 데이터가 필요하지 않습니다.** Opus가 직접 수행합니다.

## 범위

$1 (비어 있으면 전체)

## 입력

- 의뢰자가 제공한 시험 개요, 개발계획, IB(시험자자료집)
- `docs/` 아래 참고 문서
- 유사 시험의 기존 Protocol (있으면)

입력 자료가 부족하면 **먼저 사용자에게 요청하십시오.** 추측으로 채우지 마십시오.

## 표준 목차 (ICH E6(R2) 6항)

```
1.  일반 정보
2.  배경 정보
3.  시험 목적 (Objectives)
4.  시험 설계 (Design)
5.  대상자 선정 및 제외
6.  대상자 치료
7.  유효성 평가
8.  안전성 평가
9.  통계 (Statistics)
10. 원자료 직접 열람
11. 품질관리 및 품질보증
12. 윤리
13. 자료 취급 및 기록 보관
14. 재정 및 보험
15. 출판 방침
16. 부록
```

## 통계 분석과 직결되는 절 — 특히 정확히 쓸 것

이후 `/draft-sap`이 이 부분을 근거로 SAP를 작성합니다.
여기가 모호하면 SAP도 모호해지고, 결국 잘못된 분석이 됩니다.

### 3. 시험 목적

주요/부차 목적을 구분하고, 각각에 대응하는 평가변수를 명시합니다.

### 4. 시험 설계

- 시험 유형 (무작위배정, 눈가림, 대조군, 다기관 여부)
- 배정비
- 시험 기간과 방문 일정
- 중간분석 유무

### 5. 대상자 선정 및 제외

**번호를 붙여 나열합니다.** 이후 분석군 정의와 위반 판정의 근거가 됩니다.

### 7~8. 평가

각 평가변수마다:
- 측정 시점 (방문)
- 측정 방법
- 단위
- baseline 정의

### 9. 통계

- 주요 평가변수와 분석 방법
- **분석군 정의** (Safety Set, FAS, PPS) — SAP가 flag 변수로 옮깁니다
- 표본 크기 산출 근거
- 결측 데이터 처리 원칙
- 중간분석 계획
- 다중성 조정

## 작성 원칙

1. **추측으로 채우지 마십시오.** 확인할 수 없는 항목은 `[확인 필요: ...]`로 표시합니다.
2. **숫자를 만들어내지 마십시오.** 표본 크기, 목표 등록 수는 의뢰자 제공 값만 씁니다.
3. **규제 문구를 임의로 인용하지 마십시오.** 필요하면 출처를 명시하고 확인을 요청합니다.
4. 국문 Protocol이면 용어를 KFDA/식약처 표준에 맞춥니다.

## 출력

`docs/protocol.md`

```markdown
# 임상시험계획서 — {STUDY_ID}

버전: 0.1 (초안)
작성: Claude Opus (초안) — **시험책임자 및 의뢰자 검토 필수**
작성일: {날짜}

> 이 문서는 LLM이 작성한 초안입니다.
> IRB 제출 전 시험책임자, 의뢰자, 규제 담당자의 검토와 승인이 필요합니다.

## 확인이 필요한 항목

- [ ] (판단할 수 없었던 항목)
```

## 주의

Protocol은 규제 제출 문서이며 IRB 심의 대상입니다.
LLM 초안은 출발점일 뿐이며, 반드시 사람의 검토와 승인을 거쳐야 합니다.
