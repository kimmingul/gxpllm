# 감사 증적 검증

감사 로그의 해시 체인과 run 산출물의 정합성을 확인합니다.

**주기적으로(예: 월 1회) 실행해 결과를 보관하면 감사 대응 증적이 됩니다.**

## 실행

```bash
python scripts/verify_audit.py --study ${1:-.}
```

## 검증 항목

| 항목 | 내용 |
|---|---|
| 해시 체인 | seq 연속성, prev_hash 연결, entry_hash 재계산 일치 |
| manifest 존재 | `run_finished` 항목이 가리키는 manifest.json이 실제로 있는가 |
| 실행 로그 해시 | manifest가 기록한 로그가 변조되지 않았는가 |
| 고아 run | 감사 기록 없는 run 디렉터리가 있는가 (runner 우회 흔적) |

## 결과 해석

### 통과

감사 증적이 일관됩니다. 다만 아래 한계를 함께 이해해야 합니다.

### 실패 — seq 불일치 / prev_hash 불일치

**중간 항목이 삭제되거나 삽입되었습니다.** 조사가 필요합니다.

### 실패 — entry_hash 불일치

**항목 내용이 변조되었습니다.** 해당 run의 산출물을 신뢰할 수 없습니다.

### 실패 — 실행 로그 해시 불일치

manifest 기록 이후 로그 파일이 수정되었습니다.

### 실패 — 고아 run 발견

runner를 거치지 않고 만들어진 산출물이거나, 감사 항목이 삭제된 흔적입니다.

## 알려진 한계 — 보고 시 반드시 함께 전달

이 검증은 **변조를 탐지할 뿐 방지하지 못합니다.**

| 한계 | 설명 |
|---|---|
| 후미 절단 | 마지막 N개 항목을 지우면 남은 체인은 여전히 유효합니다. **탐지되지 않습니다.** |
| 키 접근 | HMAC 키는 사용자 프로필(`~/.gxpllm/audit.key`)에 있습니다. 같은 PC의 같은 사용자는 접근할 수 있습니다. |
| 외부 anchor 없음 | WORM 저장소나 원격 타임스탬프가 없습니다. |
| 성공 접근 미기록 | 차단된 접근(`access_blocked`)과 셸 명령은 기록되지만, 허용된 파일 읽기는 기록되지 않습니다. |

### 보완 방법

1. **`audit/`와 `logs/`를 백업되는 사내 공유 드라이브에 일 1회 동기화**하십시오.
   후미 절단은 백업본과 대조해야 탐지됩니다.
2. 검증 결과를 날짜별로 보관하십시오. 항목 수가 줄었다면 절단 신호입니다.
3. 제출 경로 산출물이라면 WORM 저장소 도입을 검토하십시오.

## 실패 시 조치

1. **제출 경로 산출물 사용을 중단**하십시오.
2. 백업본과 대조해 어디서부터 어긋났는지 확인합니다.
3. 해당 기간의 run을 재실행해 결과를 재현할 수 있는지 확인합니다.
4. QA에 보고하고 일탈 처리 절차를 따릅니다.

## 보고

사용자에게 보고할 것:
- 감사 항목 수, 검사한 run 수
- 서명 방식 (HMAC-SHA256 / SHA-256)
- 각 검증 항목의 통과 여부
- 발견된 문제와 심각도
- **위 "알려진 한계"를 함께 명시** — 통과했다고 변조가 불가능하다는 뜻이 아닙니다
